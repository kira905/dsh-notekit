# dsh-notekit · Anchor-based Correction Notes with Byte-exact Rollback

> Append a correction note to **one line of a production document**, then roll it back
> **byte-for-byte** whenever you need to.
>
> It exists because one-off scripts that edited dozens of documents left nobody able to say
> what changed. Here: **anchor = exactly one matching line**, **rollback = LIFO line-block
> replacement with byte-level assertions**, **dry-run by default**, and **any failing
> pre-check means not a single byte is written**.

---

## Read this first

1. **Both CLIs implement `--help` / `-h`** (prints usage, exits 0, writes nothing).
   This file still does not show help examples in code blocks — the argument shapes are
   detailed; copy the tables in §4.
2. **Dry-run is the default**: without `--apply`, both `apply-note.mjs` and `restore-note.mjs`
   only pre-check. That is the opposite of tools that ignore unknown flags and act.
3. **Unknown arguments are still silently ignored** (parsing is `argv.includes` / `indexOf`,
   no allow-list). A misspelled switch will not error. For `--apply`, always run the
   non-`--apply` pre-check first and read `planned` / `changed`.
4. **It edits production documents** — back up, and dogfood with `--only <label>` first.

## 1. What it fixes

- Location commands like `rg "<keyword>"` returned **0 hits** on the target file, forcing people to
  anchor by "domain + item name" instead.
- The same add-note / rollback script was **rewritten four times** across four workstreams, hitting
  the same pitfalls each time.
- A recorded real pitfall: `$&` / `$'` / `` $` `` / `$1` in a replacement string were expanded as
  replacement patterns — duplicating a whole file (441 lines → 735).

The toolkit hard-codes those lessons: all writes are **byte-slice splices**, never `String.replace`.

## 2. Quick start

```powershell
node apply-note.mjs --plan plans/example.json            # pre-check (dry-run)
node apply-note.mjs --plan plans/example.json --apply    # write (only if every pre-check passed)
node restore-note.mjs --manifest plans/example.manifest.json --apply   # LIFO rollback
node selftest.mjs                                         # 66 assertions (incl. 8 must-fail cases)
node drill.mjs                                            # 11-stage fixture drill, 28 assertions
```

`drill.mjs` also accepts **optional** read-only evidence files as arguments: it hashes them before
and after and asserts equality, and never applies/restores them. No arguments = touch nothing outside
the fixture tree.

## 3. Plan file (plan.json)

```jsonc
{
  "mark": "YOUR-MARK-2026",                       // required: idempotency key + rollback locator
  "noteHeader": "<br>🪪 **Correction note (…)**：",  // optional, auto-generated by default
  "targets": [
    {
      "file": "X:\\docs\\example-table.md",        // required: absolute path
      "label": "R-038 row",                       // required: unique; used by manifest / --only / --target
      "anchor": { "mode": "prefix", "text": "| **R-038** |" },
      "insert": "before-trailing-pipe",
      "note": "note body (**must not contain a pipe |** — it would split the Markdown table)"
    }
  ]
}
```

| `anchor.mode` | Match rule | Typical use |
|---|---|---|
| `prefix` | prefix equality | "domain + item name" |
| `contains` | substring | when the line start is unstable |
| `exact` | whole-line equality | rarely |
| `block` (multi-line `text`) | each line equal ⇒ a block | anchor a section heading |

`insert`: `end` · `before-trailing-pipe` (before the trailing `|`, keeps tables closed) ·
`after-anchor` (single-line anchors only).

**Exactly one match is required**; 0 or ≥2 matches refuse to act. With a `block` anchor the
**last line of the block** is the one edited.

LF/CRLF: newlines inside anchors are normalised to `\n` and matched per logical line, so one plan
works on both EOL styles; the idempotency guard counts both variants and takes the larger.

| Argument | Meaning |

## 5. Built-in discipline

1. Anchor by item prefix; **≠ 1 match ⇒ refuse** (both EOL variants tried).
2. **Idempotency guard**: refuse if the new line text already exists, or if the line already
   contains `mark` ⇒ repeated `apply` is refused (including the historically missed "old ⊂ new"
   insertion shape).
3. **Rollback = strict LIFO + line-block replacement + byte assertions**; never restore by copying
   the whole before-snapshot back.
4. **Dry-run is the first gate inside the write function**, not an external wrapper.
5. **Transactional**: all files/targets pre-checked ⇒ re-read everything before writing (concurrent
   writer guard) ⇒ then write. Any failure ⇒ **zero bytes written**.
6. Multiple edits in one file: applied in **descending byte offset** order, written once.
7. Byte-slice splices only — `$&` / `$'` / `` $` `` / `$1` are **data, not patterns**.
8. Per-line EOL preserved (including mixed-EOL files); BOM preserved; only targeted lines change.

---

## 6. How rollback locates an insertion

Each manifest record stores `beforeLine` and `afterLine`. Their **longest common prefix L / suffix S**
give the inserted span. The restorer scans the file for a line that can be reduced back to
`beforeLine` (prefix + suffix match, span contains `mark`, result byte-equal). Exactly one hit ⇒
remove the span. Zero hits with one pristine line ⇒ already rolled back (rc 0). Zero hits and no
pristine line ⇒ refuse. Two or more hits ⇒ refuse (ambiguous).

## 8. Known limits

- **I/O failure during the write phase** is not rolled back (files already written stay written).
  Use small batches and roll back via the manifest.
- A note body containing a half-width `|` is refused (Markdown table safety).
- **No cross-process file lock**: guard is "re-read everything right before writing".
- `--expect-file-sha` misfires if another process writes the file concurrently.
- Fixtures live under the system temp directory (`<tmp>/dsh-notekit-*`); `safeReset` refuses to
  delete anything outside that prefix.

# dsh-notekit · 锚定式「加订正注 / 回滚」器具

> 给一份**生产文档的某一行**追加一条订正注，并且在需要时**逐字节**撤回来。
>
> 它解决的是"用一次性脚本改了几十条文档、事后谁也说不清改了什么"的问题：
> **锚定 = 行级唯一命中**，**回滚 = LIFO 行级块替换 + 逐字节断言**，
> **默认 dry-run**，任何一个目标预检失败 ⇒ **整批一个字节都不写**。

---

## ⚠️ 先读这段（比任何用法都重要）

1. **两个 CLI 都实现了 `--help` / `-h`**（打印用法后 `exit 0`，**不写盘**）。
   但本文件**不在代码块里给帮助示例** —— 参数写法细节多，照 §3 的逐件参数表抄最稳。
2. **默认就是 dry-run**：`apply-note.mjs` 与 `restore-note.mjs` 不加 `--apply`
   都只预检、不写盘。这一点与"未知参数被忽略后直接执行真动作"的小工具**相反**，
   但仍有第二个坑 ↓
3. **未知参数仍会被静默忽略**（参数解析是 `argv.includes` / `indexOf`，没有白名单）。
   ⇒ 拼错的开关**不会报错**，脚本会按它认识的那几个参数继续跑。
   对 `--apply` 档尤其要小心：先跑不含 `--apply` 的预检，看清「planned / changed」再真写。
4. **它写的是「生产文档」**：请先备份 / 先在小批上 dogfood（`--only <label>`）。

---

## 1. 它解决什么问题

- 卡作者拿到的定位命令（例如 `rg "<某关键词>"`）在目标档里 **0 命中** ⇒ 现场只能临时改用
  「**域名 + 项名**」锚定。
- 同一件事的「加注 / 回滚」脚本，**在 4 条业务线各重写了一份**，每次都踩一遍同样的坑。
- 已记录的**真坑**：替换串里的 `$&` / `$'` / `` $` `` / `$1` 被当替换模式展开 ——
  实测把整份文件复制了一遍（441 行 → 735 行）。

本器具把这套做法固化，并把上述坑**写死在实现里**（调用方绕不过）：
落盘一律**字节切片拼接**，不用 `String.replace`。

## 2. 六十秒上手

```powershell
# ① 预检（默认就是 dry-run —— 只说不做）
node apply-note.mjs --plan plans/example.json

# ② 真写（预检全绿才会写；任一失败 ⇒ 一个字节都不写）
node apply-note.mjs --plan plans/example.json --apply

# ③ 一行式回滚（默认 dry-run，加 --apply 才真撤）
node restore-note.mjs --manifest plans/example.manifest.json --apply
```

自测 / 演练（都只碰**系统临时目录**下的自建夹具树，**生产零接触**）：

```powershell
node selftest.mjs    # 66 项断言（含 8 组「反例必红」+ 纪律自检）
node drill.mjs       # 夹具树 11 阶段演练 28 项断言
```

> `drill.mjs` 额外支持**可选**的「只读生产档 sha 取证」：把文件路径当参数传给它，
> 它只算跑前/跑后 sha 并断言一致，**绝不**对这些文件执行 apply/restore。
> 零参数 = 不碰任何外部档。

## 3. 计划文件（plan.json）

```jsonc
{
  "mark": "YOUR-MARK-2026",                                 // 必填：幂等判据 + 回滚定位（noteHeader+note 里必须出现）
  "noteHeader": "<br>🪪 **订正注（2026-10-15 · 卡「xxx」执行会话 · 只加注、判定列一字未动）**：",  // 可选，缺省自动生成
  "targets": [
    {
      "file": "X:\\docs\\example-table.md",                  // 必填：绝对路径
      "label": "R-038行",                                   // 必填：唯一；manifest / --only / --target 都按它点名
      "anchor": { "mode": "prefix", "text": "| **R-038** |" },
      "insert": "before-trailing-pipe",
      "note": "注文正文（**禁含半角竖线 |** —— 会被 Markdown 当列分隔，器具直接拒动）"
    }
  ]
}
```

### 3.1 锚定（`anchor.mode`）

| mode | 判据 | 典型用法 |
|---|---|---|
| `prefix` | **行首前缀**相等 | 「域名 + 项名」= `\| **R-038** \|` |
| `contains` | 行内**包含** | 无稳定行首时用 |
| `exact` | 整行**全等** | 极少用 |
| `block`（多行 `text`） | `text` 里带换行 ⇒ 逐行**全等**匹配一块 | 锚一段小节标题 |

> **命中数必须恰 1**，否则拒动（0 命中、≥2 命中都不动手）。多行块锚点下，**真正被改的是块末行**。

### 3.2 插入点（`insert`）

| 值 | 落点 |
|---|---|
| `end` | 行尾追加 |
| `before-trailing-pipe` | 行尾 `\|` **之前**（表格行保持列闭合；非表格行退化为行尾） |
| `after-anchor` | 锚点子串**之后**（仅单行锚点） |

### 3.3 LF / CRLF 双变体

锚点文本里的换行一律先归一成 `\n`，再按「逻辑行」匹配 ⇒ **同一份计划对 LF 与 CRLF 文件都成立**；
幂等守卫也把两种 EOL 变体各数一遍、取较大命中数。

## 4. 命令（**唯一权威参数表**）

### 4.1 `apply-note.mjs` —— 加注（默认 dry-run）

| 参数 | 说明 |
|---|---|
| `--plan <path>` | 计划文件（**必填**） |
| `--apply` | 真写盘；缺省 = dry-run |
| `--only <label>` | 只处理某个 label（演练 / dogfood 用） |
| `--manifest-out <path>` | 回滚 manifest 落点（缺省 `<计划名>.manifest.json`，与计划同目录） |
| `--before-dir <path>` | 改前副本目录（**仅作证据**，回滚器不读它；缺省 `<manifest 同目录>/.before`） |
| `--json` | 以 JSON 摘要输出 |
| `--help` / `-h` | 打印用法（不写盘） |

退出码：`0` 成功（含 dry-run 预检全绿）· `2` 用法错 · `3` 计划文件不存在/非法 JSON · 其它 = 预检失败。

### 4.2 `restore-note.mjs` —— 回滚（默认 dry-run）

| 参数 | 说明 |
|---|---|
| `--manifest <path>` | apply 产出的 manifest（**必填**；回滚器唯一输入） |
| `--apply` | 真写盘；缺省 = dry-run |
| `--target <label>` | 只回滚某一条（缺省全量） |
| `--expect-file-sha <file>=<sha256>` | 可选：回滚后整档 sha 断言（可多次给；**只在本档没别人动过时用**） |
| `--json` | 以 JSON 摘要输出 |
| `--help` / `-h` | 打印用法（不写盘） |

### 4.3 两个自测件

| 命令 | 说明 |
|---|---|
| `node selftest.mjs` | 66 项断言：正例 / 8 组反例必红 / LIFO 回滚 / `--help` 纪律自检 |
| `node drill.mjs [<只读取证档>…]` | 11 阶段夹具树演练；可选传入生产档做跑前/跑后 sha 取证（**只读**） |

## 5. 纪律（写死在实现里）

1. **锚定 = 项名前缀 / 域名 + 项名**；命中数 **≠ 1 即拒动**（LF / CRLF 双变体都试）。
2. **幂等守卫**：apply 前查「新行文本」是否已存在（双变体取较大命中数）+ 行内含 `mark` 也拒
   ⇒ **重复 apply 必拒**（含「old ⊂ new」的插入型，这是历史漏网过的形态）。
3. **回滚 = 严格逆序（LIFO · 按 `appliedSeq` 降序）+ 行级块替换 + 逐字节断言**；
   **绝不拿 before 快照整档覆盖**（`--before-dir` 里的副本**只作证据**，回滚器一行都不读它）。
4. **默认 dry-run**，`--apply` 才写；dry-run 是**写盘函数内的第一道门**（不是外部包装）。
5. **事务性**：全文件全 target 预检全绿 ⇒ 写前再全量重读（并发写者守门）⇒ 才逐文件写。
   任一环节失败 ⇒ **一个字节都不写**。
6. 同一文件多处修改 ⇒ 内存内按**字节偏移降序**应用 + **聚合一次写盘**（避免后写覆盖先写）。
7. 落盘一律**字节切片拼接**（不用 `String.replace`）⇒ `$&` / `$'` / `` $` `` / `$1` **当数据不当模式**。
8. **逐行 EOL 原样保留**（含 EOL 混用的文件）；**BOM 原样保留**；改写只发生在目标行内，其余字节一字不动。

## 6. 回滚器怎么定位（原理，排障时看这段）

manifest 每条记录都存了 `beforeLine`（原行）+ `afterLine`（加注后行），由两者的
**最长公共前缀 L / 最长公共后缀 S** 得出「插入区间」。回滚时扫描目标文件的每一行：

- 找 `能还原成 beforeLine` 的行（前缀匹配 + 后缀匹配 + 中间段含 `mark` + 还原结果**逐字节等于** `beforeLine`）；
- 命中**恰 1** ⇒ 拔掉插入区间、就地替换；
- 命中 **0** 且文件里恰有 1 行 `== beforeLine` ⇒ **幂等跳过**（已经回滚过了，rc=0）；
- 命中 **0** 且没有原始态行 ⇒ **拒动**（撤销目标已不存在）；
- 命中 **≥2** ⇒ **拒动**（歧义，宁可不动）。

**注内被改字**（比如有人在注文里改了个错别字）⇒ 仍能正确还原（前后缀判据不受影响）。
**注外被改**（注之前的项名/内容被改）⇒ 前缀失配 ⇒ **拒动**，不静默。

## 8. 已知边界（如实登记）

| 边界 | 现状 |
|---|---|
| 写盘阶段的 IO 级失败 | 预检 + 写前重读已挡住所有**可判定**失败；但逐文件写盘途中若发生 IO 异常，**已写下的文件不撤回**。多文件批建议小批走、失败后按 manifest 回滚已写部分。 |
| 注文含半角 `\|` | 直接拒动（保护 Markdown 表格列）。 |
| 跨进程并发 | 靠「写前全量重读比对」挡；读与写之间的极窄窗口**不做文件锁**。 |
| `--expect-file-sha` | 只在**确定该档没有别的进程在写**时用；否则会误报。 |
| 夹具目录 | 固定在系统临时目录（`<tmp>/dsh-notekit-*`）；`safeReset` 按「临时目录前缀 + 名字前缀」双判据拒删其它路径。 |
